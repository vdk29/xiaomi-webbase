# Сетевые остатки Xiaomi WebBase

Сетевая база расширяет существующую WebBase и использует тот же Supabase `dazniyfntumbljkocjoo`, авторизацию и приватный бакет `webbase-products`. Локальные остатки `webbase_stock` обновляются только отдельным локальным импортом. Сетевой импорт их не создаёт и не меняет.

## Пользовательский сценарий

- **Остатки по сети** доступны активным сотрудникам: поиск, фото, цвет/память, регион, страницы по 24 позиции. По умолчанию — Москва; LDU скрыты отдельным переключателем.
- Из любой действующей карточки кнопка **Наличие в других магазинах** открывает диалог по UUID выбранной модификации. Основной каталог повторно не читается. Есть сортировки по складу, количеству, наличию и названию; переключатель нулевых остатков; исходные учётные склады раскрываются отдельно.
- Дата обозначена как **«Наличие по данным от …»**. Это снимок отчёта, а не онлайн-доступ к кассе.
- Склад, ОВ и брак раздельны. «Всего» = склад + ОВ; брак и LDU не увеличивают доступное количество. Отрицательные значения сохранены и отмечены. LDU остаются самостоятельными позициями с пометкой «не для продажи».
- Новые обычные карточки участвуют в основном каталоге и поиске, имеют нулевой локальный остаток и метку каталога сети. Неполные сведения помечаются для проверки. Обычный каталог рисует первые 48 карточек, затем «Показать ещё».

## Импорт администратора

Открыть **Импорт сети**, выбрать XLSX и нажать **Импортировать и обновить каталог**. Импорт независим от «Импорт 1С» нашего магазина.

1. XLSX разбирается в Web Worker. Определяются строка номенклатуры, строка количества, склады, общий итог, дата и иерархия.
2. Группа — строка, за которой идёт более глубокий уровень; её количество повторно не суммируется. Реальные строки определяются независимо от глубины и формата шрифта, включая товары на нулевом уровне. Смещение `!ref` листа учитывается через `range: 0`.
3. Проверяются целые количества, каждая товарная строка, каждый склад и общий итог. Отрицательные количества разрешены. Потерянная иерархия блокирует публикацию: нельзя достоверно отличить итог от товара.
4. SHA-256 исходного файла даёт идемпотентность. Проверенные строки передаются пакетами по 75 в закрытую staging-таблицу. Исходный XLSX остаётся в браузере, в публичный репозиторий/Storage не загружается.
5. Одна транзакция под advisory lock проверяет полноту staging, связывает товары, создаёт недостающие карточки, записывает сетевой снимок и меняет активную версию. Ошибка откатывает этот этап целиком. Более старый отчёт не заменяет свежий.
6. Заполнение изображений/описаний запускается отдельно и не задерживает остатки. Закрытие страницы не останавливает серверную очередь. Повторить незаполненные карточки можно без нового Excel.

В административной вкладке также есть **Магазины и склады** и **Товары, требующие проверки**. Можно создать/редактировать проверенный магазин и его регион/адрес, изменить назначение склада, исключить служебный склад, исправить связь или открыть карточку для ручного дополнения. Сопоставления сохраняются между импортами.

## Идентичность и сохранность данных

`network-identity.js` нормализует регистр, пробелы, GB/ГБ, 1 TB/1024 GB, запись ОЗУ/накопителя и известные цветовые обозначения. Полное название модели, память, оттенки и LDU остаются частью товарной идентичности. Масштаб модели автомобиля `1/18` и бухгалтерский код `66/003` не считаются памятью.

Существующие UUID, артикулы, ручные названия, описания, характеристики, галереи и локальные остатки сетевой импорт не перезаписывает. Точный заводской код может подтвердить различия в формулировке только при согласованных категории, цвете, памяти и LDU; код совместимого пылесоса не объединяет с ним щётку. Неоднозначное совпадение направляется на проверку без автоматического объединения.

У новой позиции UUID и стабильный `external_id = network:<hash>`, поле неизвестного артикула остаётся пустым. Последующий локальный импорт может присвоить настоящий артикул точной активной сетевой карточке без создания дубля. Для фотографии без артикула используется постоянный внутренний ключ `network:<hash>` в существующем реестре `sku_keys`; после появления артикула сохраняются оба ключа. Удаление позиции из следующего отчёта не удаляет карточку, фото или описание.

Названия складов имеют отдельную нормализацию, без замены слов цветов/памяти. Все исходные названия и юридические лица сохранены. Группировка выполняется по сохранённым проверенным соответствиям, а не по приблизительно похожему названию. Московский Европолис и Европолис СПБ — разные идентичности. Неизвестные точки не включаются автоматически в обычные магазины.

## Обогащение карточек

`webbase-network-enrich` — Edge Function с собственной проверкой администратора либо непрозрачного серверного токена. Токен хранится в Supabase Vault; service-role используется только внутри функции.

Очередь находится в Postgres: блокировка `SKIP LOCKED`, lease на три минуты, восстановление зависшего задания, ограничение попыток. Cron проверяет её каждые 20 секунд и не вызывает HTTP при пустой очереди. Функция обрабатывает ограниченное число задач и не более двух новых изображений за вызов, чтобы учитывать лимиты CPU. История результатов импортов и источников сохраняется; только собственные технические логи Cron ограничены семью днями.

Приоритет: действующая фотография карточки → существующая галерея/проверенный осиротевший реестр → источник производителя → точная карточка магазина. Факты производителя для уже проверенных семейств смартфонов используются из существующего справочника; проверенные сведения из карточек переиспользуются с источником и исходной датой проверки. Другие товары ищутся в публичном каталоге магазина через его штатный поисковый индекс; заводской код и затем модель/цвет используются для получения кандидатов, а конечная страница проверяется повторно. Поиск производителя используется как дополнительный источник.

Фото можно разделять между объёмами памяти только одной модели и цвета. Случайный похожий аппарат и исправленный поиском другой Pro/Ultra/цвет не принимаются. Существующая или добавленная администратором фотография выигрывает у фоновой обработки. Изменение названия во время обработки переводит задачу на проверку.

JPEG/PNG уменьшаются до 960 пикселей и сохраняются JPEG quality 80 на белом фоне. Уже оптимизированный WebP принимается после проверки формата, размеров и размера файла; тяжёлый WebP направляется на дополнительную оптимизацию/проверку. SHA-256 содержимого формирует общий путь `products/<content-uuid>/<sha256>.<ext>` в прежнем приватном бакете. Повторная загрузка такого файла не создаёт копий. Base64 в БД не сохраняется. Сохраняются URL первичной страницы, исходного изображения, время получения и сведения о переиспользовании.

Значения памяти/цвета из сторонней комплектации не копируются поверх выбранной номенклатуры. Новое описание — краткая выжимка фактических характеристик; при отсутствии надёжного источника остаётся карточка из названия и задача проверки. Обогащение не гарантирует полноту для снятых с продажи моделей, редких аксессуаров или недоступных источников. Нейтральная заглушка показывает отсутствие фото, а не логотип Xiaomi или другую модель.

## Supabase

Добавлены таблицы `webbase_network_stores`, `warehouses`, `imports`, `stage`, `items`, `snapshot_items`, `stock`, `jobs`, `sources` (все с префиксом `webbase_network_`). В `webbase_products` добавлены `network_origin` и `is_demo`, существующий invoker-view каталога расширен этими полями. Реальные товары и локальные остатки не перенесены в другую базу.

RLS: активные сотрудники читают данные сети, администраторы импортируют/редактируют, staging доступен только администратору; `anon` не получает таблицы или RPC. Функции поиска/импорта работают как invoker. Привилегированные операции очереди доступны только service-role. Индексы покрывают снимок/товар/склад, идентичность, поиск, фотографии и внешние ключи.

Будущие снимки записывают только ненулевые ячейки плюс отдельный реестр всех включённых позиций: так сохраняются нулевые товары без разрастания матрицы. Существующие данные первого снимка сохранены целиком. История импортов и предыдущие снимки остаются доступными; публикация нового снимка не удаляет прежние данные.

Все миграции `20261107*_network_*.sql` применены к действующему проекту и их имена синхронизированы с `supabase_migrations.schema_migrations`. Дополнительная настройка ключей для текущего развёртывания не требуется. Код функции и её pinned-зависимости/lockfile находятся в `supabase/functions/webbase-network-enrich/`.

### Воспроизводимые проверки

```sh
npm test
npm run check
# Добавить закрытый файл только через переменную окружения, не в Git:
WEBBASE_NETWORK_REPORT=/path/to/private-report.xlsx npm test
WEBBASE_NETWORK_REPORT=/path/to/private-report.xlsx node scripts/verify-network-ui.cjs
npx deno check --config supabase/functions/webbase-network-enrich/deno.json supabase/functions/webbase-network-enrich/index.ts
npx deno test --allow-net=deno.land --config supabase/functions/webbase-network-enrich/deno.json tests/network-images.deno.ts tests/network-sources.deno.ts
```

`tests/network-inventory.sql` выполняется в текущем Supabase с откатом: публикация/повторный импорт/ошибка неполного снимка, обычный товар и LDU, брак, регионы, ручные поля, фотографии без SKU и последующее присвоение SKU, отсутствие локальных записей у новых сетевых товаров, запрет анонимного/неактивного доступа. Частный XLSX в тестовый репозиторий не включён.

Браузерный сценарий использует реальное приложение и реальный разбор частного XLSX с изолированным API: 320/390/1440 пикселей, debounce, страницы, регионы, количества, склад/ОВ/брак, отрицательные значения, точный UUID карточки, закрытие диалога, административный импорт и скрытие его от сотрудника. Дополнительно проверены прежний локальный импорт и компактная помощь продавцу.

- `js/network-parser.js`, `network-identity.js`, `network-import-worker.js` — разбор и идентичность.
- `js/network-stock.js`, `network-stock.css` — поиск и диалог.
- `js/network-admin.js` — импорт, статистика, справочники и проверка.
- `index.html`, `webbase-app.js`, `product.html`, `product.js` — интеграция меню/карточек.
- `js/products.js`, `catalog.js`, `importer.js`, `images.js`, `listing-navigation.js`, `utils.js` — сохранение текущих сценариев, фотобанк, поиск и пагинация.

- `tests/network-*`, `scripts/verify-network-ui.cjs` — проверки.
