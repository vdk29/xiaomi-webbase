# Xiaomi WebBase

Внутренний каталог магазина Xiaomi на GitHub Pages и Supabase.

Восстановление после сетевых обрывов:
[docs/NETWORK_RECOVERY.md](docs/NETWORK_RECOVERY.md).

Раздел «Совместимость», условия подбора расходников и источники:
[docs/COMPATIBILITY.md](docs/COMPATIBILITY.md).

Заполнение описаний и перечень позиций для уточнения:
[docs/DESCRIPTION_COVERAGE.md](docs/DESCRIPTION_COVERAGE.md).

## Возможности

- вход по регистронезависимому логину и паролю; прежний email администратора поддерживается;
- роли `admin` и `staff`, активная блокировка на уровне RLS;
- каталог с поиском, фильтрами, сортировкой и отдельными UUID-страницами товаров;
- редактирование карточки и остатков только администратором;
- приватная галерея Supabase Storage с signed URL, сжатием WebP и сортировкой;
- административное управление сотрудниками через Edge Function;
- предпросмотр Excel и транзакционный импорт 1С без перезаписи ручных полей и фотографий.

## Развёртывание

1. Применить `supabase/migrations/20261023210000_complete_webbase.sql`.
2. Развернуть `supabase/functions/webbase-create-staff/index.ts` с `verify_jwt = true`.
3. Убедиться, что бакет `webbase-products` приватный и ограничен 5 МБ / JPG, PNG, WebP.
4. Опубликовать ветку через GitHub Pages.

В браузерном коде хранится только publishable key. Secret/service-role key используется исключительно внутри Edge Function.

## Сохранение фотографий по артикулу

Миграция `20261024073412_persistent_sku_images.sql` сохраняет метаданные фото
при DELETE карточек: `product_id` становится NULL, полные артикулы остаются в
`sku_keys`, а файл остаётся в приватном Storage. При повторном импорте с теми же
артикулами фото привязываются к новым UUID. Артикулы сравниваются целиком без
учёта регистра; последние четыре цифры используются только для поиска.
При неоднозначных артикулах автоматическая привязка пропускается. Не удаляйте
`webbase_product_images` и файлы Storage при очистке каталога; TRUNCATE CASCADE
и ручное удаление самих файлов не являются поддерживаемой очисткой.

База и интерфейс ограничивают карточку тремя фотографиями. Самостоятельное
удаление фотографии из галереи удаляет её окончательно. Проверка удаления и
повторного импорта: `tests/photo-reimport.sql` (все тестовые записи откатываются).
Состояние наполнения: [docs/PHOTO_COVERAGE.md](docs/PHOTO_COVERAGE.md).

Фотографии подбираются отдельно для модели и цвета; рекламные баннеры,
комплекты подарков и изображения нескольких цветовых вариантов не допускаются.
`scripts/prepare-photo-assets.py` готовит WebP 640×640 с белыми полями без
изменения цвета товара. Проверенный источник и SHA-256 записаны в манифесте.
Функция `webbase-import-official-images` доступна только активному администратору:
POST `{ "action": "stage", "start": 0 }` выдаёт signed upload URL для следующих
10 подготовленных файлов, `verify` проверяет SHA-256 загруженных файлов,
`attach` добавляет проверенные записи в галерею без дубликатов. Сырые фотографии
из интернета функция больше не скачивает. Временные полномочия первоначального
заполнения не входят в исходный код функции.

Каталог получает подписанные ссылки пакетом. Действующие ссылки кэшируются на
12 минут в sessionStorage отдельно для каждого пользователя и проекта.
Первые восемь видимых изображений загружаются сразу, остальные — при прокрутке.

Браузерная проверка (Playwright установлен отдельно):
`WEBBASE_TEST_CREDENTIALS_FILE=/path/to/test-login.json node scripts/verify-photo-browser.cjs`.
Файл содержит `email` и `password` тестового сотрудника; URL по умолчанию —
`http://127.0.0.1:4173`. Проверка читает данные и фотографии, обновляет страницы
и проверяет приоритет поиска по окончанию артикула. Учётные данные не входят в Git.

Проверка размеров, отсутствия перекрытий и числа запросов подписанных ссылок:
`WEBBASE_TEST_CREDENTIALS_FILE=/path/to/test-login.json node scripts/verify-photo-layout.cjs`.
Для проверки кнопок галереи используйте отдельную тестовую учётную запись администратора.

## Общие фотографии для вариантов памяти

Миграция `20261024100914_shared_model_color_photos.sql` добавляет подбор галереи
для смартфонов и планшетов по полному названию модели и цвету без RAM/накопителя.
Например, `Xiaomi 17T Pro 12GB+256GB Black` и `Xiaomi 17T Pro 16GB+1024GB Black`
используют одну галерею, если у второго товара нет собственных фотографий.
Различия Pro/Max, 4G/5G, бренда и полного оттенка сохраняются. Неизвестный или
отсутствующий цвет не угадывается. Поддерживаются обозначения GB/ГБ/TB/ТБ,
комбинации `12GB+256GB` и `12/256 GB`, цвет до или после памяти.

RPC `webbase_shared_product_images` читает данные с правами сотрудника и RLS.
Каталог и отдельная карточка получают одинаковую галерею, в том числе после
обновления страницы. Выбирается одна галерея до трёх фото, без копирования
файлов в Storage. Собственная загрузка заменяет общую галерею для этой карточки.
Управление общими фото доступно в исходной карточке: удаление исходного файла
уберёт его и у использующих его вариантов. Подпись «Фото модели и цвета»
обозначает общие фото; кнопки удаления и перестановки для них скрыты.

Ключ модели/цвета сохраняется вместе с метаданными фото даже при удалении
товара. Поэтому новая память может получить галерею до возвращения исходного
артикула. Фото архивных карточек не используются. Изменение названия исходной
карточки обновляет ключ её фото. Транзакционный тест импорта, собственных фото,
разделения моделей/цветов, восстановления и RLS: `tests/shared-photos.sql`.
Браузерный тест каталога, карточки, обновления страницы и управления общей
галереей с изолированными данными: `node scripts/verify-shared-photo-ui.cjs`
(Playwright, локальный сервер на порту 4173; `CHROMIUM_PATH` при необходимости).
